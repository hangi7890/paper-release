# BDG2 v5 최종 시험 분석 프로토콜 초안

## 1. 문서 상태와 적용 범위

이 문서는 기존 C0 개발 결과를 바탕으로 **최종 시험 전**에 고정할 분석 절차의 초안이다. 개발 결과를 이미 본 뒤 작성했으므로 전향적 사전등록으로 표현하지 않는다. 연구자가 이 초안과 최종 시험 대상 manifest를 승인하고 해시를 고정한 뒤에만 독립 최종 시험을 실행할 수 있다.

- 입력 조건 C0: 과거 전력 24시간과 예측 대상 24시간의 사전 가용 달력 특성.
- 출력: 직후 24시간 전력 계량 기록.
- 적응 예산: `0, 1, 3, 7, 14, 28`일.
- 주 평가: 건물마다 고정된 28개 일별 예측 창. 창은 24시간 간격으로 시작하고, 서로의 정답 시각이 겹치지 않는다.
- 모델: 기존 Source 20개 건물로 학습·선택한 C0 LSTM과 기존 output-head-only 적응 절차. 이 프로토콜 때문에 모델 구조나 학습 설정을 다시 조정하지 않는다.
- 개발 분석: 기존 개발 12개 건물, 6개 사이트, 시드 `20260924, 20260925, 20260926`.
- 최종 시험: 기존 `final_test_proposal`의 사이트 단위 분리를 유지한다. 정확한 건물 목록과 시간 경계는 연구자 승인 전에 별도 최종 manifest로 고정해야 한다.
- 금지 범위: C1 기상 입력, 실내 센서, 신규 모델, 최종 시험 결과를 이용한 튜닝·제외·임계값 변경.

이 문서 작성 과정에서 최종 시험 사이트의 전력값을 읽거나 분석하지 않았고, 최종 모델 학습이나 평가도 실행하지 않았다.

## 2. 개발 결과에서 확인된 신호와 해석 경계

다음 수치는 가설을 만든 **개발용 탐색 근거**이며 최종 시험 결과가 아니다.

| 적응 예산 | 실제 Target 학습 창/건물 | Source-only 대비 MAE 개선 건물×시드 | F1 사건 | 두 단순 기준선보다 MAE가 작은 건물×시드 |
|---:|---:|---:|---:|---:|
| 1일 | 1 | 10/36 | 26/36 | 4/36 |
| 3일 | 49 | 25/36 | 11/36 | 10/36 |
| 7일 | 145 | 30/36 | 6/36 | 11/36 |
| 14일 | 313 | 30/36 | 6/36 | 12/36 |
| 28일 | 649 | 35/36 | 1/36 | 16/36 |

28일의 건물별 시드 평균에서는 12/12개 건물이 Source-only보다 MAE가 작았지만, 전일·전주 두 기준선을 모두 이긴 건물은 6/12개였다. 따라서 아래 프로토콜은 `Source-only 대비 개선`과 `단순 기준선 추월`을 같은 성공으로 취급하지 않는다.

실패 사건은 적응일이 늘수록 전반적으로 감소했지만 1일 적응은 F1 26/36, F2 25/36이었고, 28일에도 F3-any가 20/36이었다. 개발 12개 건물에서 관찰한 이 양상을 BDG2 전체의 일반 법칙으로 표현하지 않는다.

특성 탐색에서는 예산별로 서로 다른 상관이 가장 크게 관찰되었고, 모든 상관은 `n=12`에서 여러 후보를 확인한 사후 탐색이다. 상관의 크기나 방향을 자동 제외 규칙, 인과관계 또는 확정적 실패 예측기로 사용하지 않는다.

## 3. 고정 분석 단위와 비교 집합

### 3.1 예측 및 오차 단위

건물 `b`, 시드 `s`, 적응 예산 `d`, 예측 대상 시간 `t`에 대해 실제값을 `y(b,t)`, 예측값을 `ŷ(b,s,d,t)`로 둔다.

- 한 건물의 주 평가점 수: `28창 × 24시간 = 672시간`.
- 각 예산의 Target 학습 창 수: `N(0)=0`, `N(1)=1`, `N(3)=49`, `N(7)=145`, `N(14)=313`, `N(28)=649`.
- `d>0`의 창 수는 `24d-23`이다.
- 0일은 Target 정답으로 가중치를 갱신하지 않는 Source-only 조건이다.

### 3.2 반드시 동일해야 하는 비교 대상

한 건물에서 Source-only, 모든 적응 예산, 전일 기준선, 전주 기준선은 다음을 공유해야 한다.

1. 동일한 28개 forecast origin.
2. 동일한 672개 정답 timestamp와 실제값.
3. 동일한 사전 고정 시험 시작·종료 시각.
4. 동일한 C0 입력 가용성 규칙.

예산별로 성능이 좋아지는 기간만 선택하지 않는다. 한 모델에서 평가할 수 없는 창이 있으면 그 창을 다른 모델에서만 남기지 않고, 사전 정의된 공통 비교 집합 규칙을 적용한다. 고정 28창을 충족하지 못한 건물은 `data_integrity_failure`로 남기고 대체 건물이나 이동한 기간을 사후 선택하지 않는다.

### 3.3 독립성

- 세 시드는 반복 학습 결과이며 독립 건물 표본으로 세지 않는다.
- 건물은 사이트 안에 군집되어 있다.
- 건물 요약은 먼저 시드 평균을 계산한다.
- 전체 추론의 독립 군집 단위는 사이트로 둔다.
- 건물·사이트·시드 수준 결과를 모두 공개하며, 시간점 672개를 독립 표본으로 간주한 유의성 검정을 하지 않는다.

## 4. 데이터 효율성 지표와 계산식

### 4.1 기본 오차

건물·시드·예산의 공통 정답 집합을 `T_b`라 하고 `|T_b|=672`라 할 때:

```text
MAE(b,s,d)  = (1 / |T_b|) × Σ[t∈T_b] |ŷ(b,s,d,t) - y(b,t)|
RMSE(b,s,d) = sqrt((1 / |T_b|) × Σ[t∈T_b] (ŷ(b,s,d,t) - y(b,t))²)
```

시간점 가중 평균을 건물 간 전체 오차로 직접 사용하지 않는다. 각 건물의 오차를 먼저 계산하여 대형 건물이나 큰 계량값이 표본 수 때문에 추가 가중되지 않게 한다.

### 4.2 Source-only 대비 절대·상대 변화

```text
ΔMAE_source(b,s,d)  = MAE(b,s,d)  - MAE(b,s,0)
ΔRMSE_source(b,s,d) = RMSE(b,s,d) - RMSE(b,s,0)

Gain_MAE(b,s,d)  = MAE(b,s,0)  - MAE(b,s,d)
Gain_RMSE(b,s,d) = RMSE(b,s,0) - RMSE(b,s,d)

Relative_gain_MAE(%)  = 100 × Gain_MAE / MAE(b,s,0)
Relative_gain_RMSE(%) = 100 × Gain_RMSE / RMSE(b,s,0)

Relative_delta_MAE(%)  = 100 × ΔMAE_source / MAE(b,s,0)
Relative_delta_RMSE(%) = 100 × ΔRMSE_source / RMSE(b,s,0)
```

`Δ`와 `Relative_delta`는 음수가 개선이고 `Gain`과 `Relative_gain`은 양수가 개선이다. 기존 v5 결과표의 `relative_change` 열은 `Relative_delta` 부호를 사용하므로 새 표에서도 두 부호 체계를 열 이름으로 명확히 구분한다. Source-only 분모가 `≤ EPS`이면 상대 변화율은 `NA`로 두며 임의 상수를 더하지 않는다.

### 4.3 적응량 증가에 따른 한계 효율

예산 순서를 `D=(0,1,3,7,14,28)`로 고정한다. 인접 예산 `d_prev → d`에서:

```text
Marginal_gain_per_day_MAE
  = [MAE(b,s,d_prev) - MAE(b,s,d)] / (d - d_prev)

Marginal_gain_per_window_MAE
  = [MAE(b,s,d_prev) - MAE(b,s,d)] / [N(d) - N(d_prev)]
```

RMSE도 같은 방식으로 계산한다. 이 값은 모델의 계산 효율이 아니라 **추가 Target 데이터 1일 또는 학습 창 1개당 관찰된 오차 변화**이다. 음수는 추가 데이터 뒤 악화되었다는 뜻이다.

0일 대비 누적 효율도 보조적으로 계산한다.

```text
Cumulative_gain_per_day_MAE(d)   = Gain_MAE(b,s,d) / d
Cumulative_gain_per_window_MAE(d)= Gain_MAE(b,s,d) / N(d), d>0
```

0일에는 분모가 없으므로 `NA`이다. 특정 예산 하나를 사후 선택하여 충분한 데이터량으로 선언하지 않고 여섯 예산의 전체 곡선을 제시한다.

### 4.4 단순 기준선 대비 차이

```text
Gap_MAE_PD(b,s,d) = MAE(b,s,d) - MAE_previous_day(b)
Gap_MAE_W(b,s,d)  = MAE(b,s,d) - MAE_weekly_same_hour(b)
```

RMSE도 별도로 계산한다. 음수일 때만 해당 기준선보다 오차가 작다. 전일과 전주 결과를 따로 보고하고, 두 기준선을 모두 이긴 경우를 별도 교집합으로 보고한다. 기준선이 필요한 과거 기록을 forecast origin 이전에 확보하지 못하면 미래값으로 채우지 않고 `NA`로 남긴다.

### 4.5 집계와 불확실성

1. 건물×시드 원값을 공개한다.
2. 건물 수준에는 세 시드 평균·표준편차·최솟값·최댓값을 기록한다.
3. 사이트 수준에는 해당 사이트의 건물별 시드 평균을 동일 가중치로 평균한다.
4. 전체 기술통계는 건물 동일 가중치와 사이트 동일 가중치를 함께 보고한다.
5. 핵심 가설의 95% 신뢰구간은 사이트를 군집 단위로 10,000회 재표집하는 percentile bootstrap, 난수 시드 `20260925`를 사용한다. 각 재표집 사이트 안에서는 고정된 건물을 모두 유지한다.
6. 최종 채택 사이트가 5개 미만이면 군집 bootstrap에 기반한 확정적 추론은 `판단 불가`로 두고 기술통계만 보고한다. 이 기준은 결과를 본 뒤 변경하지 않는다.

## 5. F1~F4 실패 정의와 보고 방법

부동소수점 동률 판정용 `EPS=1e-12`를 유지한다. 이는 과학적 최소효과 임계값이 아니다.

비제로 예산 `d∈{1,3,7,14,28}`에서:

- **F1:** `ΔMAE_source(b,s,d) > EPS`.
- **F2:** `ΔRMSE_source(b,s,d) > EPS`.
- **F3-PD:** `Gap_MAE_PD(b,s,d) > EPS`.
- **F3-W:** `Gap_MAE_W(b,s,d) > EPS`.
- **F3-any:** F3-PD 또는 F3-W.
- **F3-both:** F3-PD와 F3-W가 모두 참.
- **F4:** 같은 건물·예산의 세 시드에 `ΔMAE_source < -EPS`인 시드와 `ΔMAE_source > EPS`인 시드가 모두 존재.
- **지표 방향 불일치:** `ΔMAE_source < -EPS`이면서 `ΔRMSE_source > EPS`인 건물×예산×시드 사건.

`|Δ|≤EPS`인 정확한 동률은 개선과 악화 어느 쪽에도 넣지 않는다. F4는 사전 고정한 세 시드가 모두 정상 완료된 건물×예산에서만 판정하며, 하나라도 없으면 `NA`와 실패 사유를 기록한다.

### 5.1 분모

- F1~F3: 건물×예산×시드 사건. 예산별 분모는 `평가 가능한 건물 수 × 3`, 전체 분모는 여기에 5개 비제로 예산을 곱한다.
- F4: 건물×예산 사건. 예산별 분모는 평가 가능한 건물 수, 전체 분모는 여기에 5를 곱한다.
- 시드 평균 F1/F2: 건물×예산 사건으로 따로 표시하며 개별 시드 사건을 대체하지 않는다.
- `NA`는 분모에서 조용히 빼지 않고 건물·예산·시드와 사유를 별도 표에 기록한다.

### 5.2 반복 실패와 대표 사례

- 건물별로 F1·F2 발생 예산 수와 시드 사건 수를 모두 보고한다.
- 개발 분석에서 고정한 대표 사례 규칙을 최종 시험에도 그대로 적용한다.
  1. 반복 F1: 시드 평균 F1 예산 수가 가장 많은 건물. 동률이면 최대 시드 평균 `ΔMAE_source`, 그다음 `building_id` 오름차순.
  2. F4: 시드별 `ΔMAE_source` 범위가 가장 큰 건물×예산. 동률이면 `building_id`, 예산 오름차순.
  3. MAE 개선·RMSE 악화: 존재하면 `ΔRMSE_source`가 가장 큰 사건. 없으면 `없음`으로 보고한다.
- 선정한 사건의 672시간 실제값, Source-only 예측, 적응 예측을 동일 축에 표시한다.
- 보기 좋은 성공·실패 사례로 교체하지 않는다.

### 6.1 Source 기준

- Source 건물의 규모 통계는 고정 Source 학습 정답 시각만 사용한다.
- 기존 모델 설정의 Source 정규화 기준은 mean `167.065197632`, population std `354.328669572`이다.
- Target과 Source의 계량 경계·물리 단위가 개별 건물마다 동일하다는 근거가 없으므로 이 변수는 `계량값 규모 차이`로만 부른다.

### 6.2 특성 분석 규칙

- 연속 특성과 `ΔMAE_source`, `ΔRMSE_source`, F1/F2/F3 사건률의 Spearman 상관을 계산한다.
- 사이트·용도는 범주별 표본 수와 사건률을 기술한다. 작은 범주를 합치지 않는다.
- 같은 건물의 예산 행은 독립 표본이 아니므로 예산별 분석을 기본으로 한다.
- 결측 특성을 0이나 평균으로 대체하지 않는다.
- p-value를 반복 계산해 유리한 특성을 선택하지 않는다.
- 복잡한 실패 분류기, 임계값 탐색, 자동 건물 제외를 수행하지 않는다.
- 연관성은 탐색적이며 인과관계로 해석하지 않는다.

## 7. 최종 시험에서 검증할 가설

모든 가설은 개발 결과에서 만들어진 사후 가설이다. 최종 시험 전 연구자 승인과 프로토콜 해시 고정을 거쳐야 독립 검증으로 해석할 수 있다.

### 7.1 핵심 가설

**H1 — 28일 적응의 Source-only 대비 MAE 개선**

- 방향: 28일 output-head 적응의 건물별 시드 평균 `ΔMAE_source`가 음수이다.
- 1차 추정량: 각 사이트 안에서 건물별 시드 평균 `ΔMAE_source`를 동일 가중 평균한 뒤, 사이트를 동일 가중 평균한 값.
- 보조 추정량: 건물 중앙값, 건물 평균, 개선 건물 비율, 세 시드 범위.
- 지지 기준 초안: 사이트 동일 가중 1차 추정량이 음수이고 사이트 군집 bootstrap 95% CI의 상한이 0보다 작다.
- 자료가 부족해 군집 추론 조건을 충족하지 못하면 `판단 불가`이며, 기준을 완화하여 지지로 바꾸지 않는다.

RMSE 방향은 핵심 가설의 지지 여부를 바꾸는 보조 확인 지표로 보고하지 않고, 별도 핵심 보조 결과로 모두 공개한다.

### 7.2 주요 부가 가설

**H2 — 1일과 28일 사이의 F1 위험 차이**

- 개발에서 1일 F1은 26/36, 28일 F1은 1/36이었다.
- 최종 시험에서는 건물별 세 시드 F1 비율을 계산하고 사이트 안에서 평균한다.
- 추정량: `site-equal F1 rate(28d) - site-equal F1 rate(1d)`.
- 방향: 음수. 이는 모든 중간 예산에서 단조 감소한다는 주장과 구분한다.

**H3 — Source-only 개선과 두 단순 기준선 추월의 차이**

- 28일에 A 성공(`ΔMAE_source < -EPS`)과 B 성공(전일·전주 MAE 모두보다 작음)을 같은 건물×시드에서 판정한다.
- 추정량: `site-equal rate(A) - site-equal rate(B)`와 A/B의 2×2 대응표.
- 방향: 양수. A는 성공하지만 B는 실패한 사건을 모두 공개한다.

H2와 H3를 확정적 가설 검정으로 사용할 경우 사이트 단위 차이에 대한 양측 exact sign-flip permutation p-value를 계산하고, 두 p-value에 Holm 보정 `α=0.05`를 적용한다. 사이트 군집 bootstrap 95% CI는 효과크기의 불확실성으로 함께 제시한다. 연구자가 이를 기술적 부가 분석으로만 승인하면 p-value 없이 효과크기와 CI를 보고한다. 이 선택은 최종 시험 전 확정해야 한다.

### 7.3 탐색 가설

다음은 개발 12개 건물에서 생성된 탐색 가설이며 핵심 가설의 성공 여부에 포함하지 않는다.

1. 1일처럼 데이터가 매우 적을 때 가용 구간의 변동성이 클수록 `ΔMAE_source`가 커질 수 있다.
2. 정보 시점상 계산 가능한 예산에서 일간·주간 반복성이 높을수록 적응 이득이 달라질 수 있다. 방향은 예산별로 따로 보고하며 전체 예산 공통 방향을 강요하지 않는다.
3. Target의 가용 계량값 규모와 Source 규모의 차이가 적응 이득 및 실패 사건률과 연관될 수 있다. 개발 결과에서 방향이 예산마다 일관되지 않았으므로 방향성 확정 가설로 쓰지 않는다.
4. 0값 비율, 변동계수, site, 건물 용도에 따라 실패 사건률이 다를 수 있다.

모든 특성 가설은 사전 가용 정보로만 계산하며, 표본 수·결측·상관계수와 방향을 모두 공개한다. 여러 특성 중 큰 상관만 골라 핵심 결론으로 승격하지 않는다.

## 8. 최종 시험 실행 전 고정 절차

### Gate 0 — 연구자 승인 전

다음을 완료하기 전 최종 시험 전력 열을 읽지 않는다.

1. 최종 시험 건물 ID, 사이트, 선정 규칙, 제외 규칙을 manifest로 고정.
2. 건물별 적응·시험 시간 경계와 28개 forecast origin을 고정.
3. 기존 source model, 세 시드, 정규화 통계, 적응 optimizer·학습률·epoch·모델 선택 규칙의 파일 해시 고정.

### Gate 1 — 성능을 보지 않는 구조 검증

승인 뒤 최초 접근에서 다음 자동 검증을 먼저 수행한다.

- 모든 건물이 기존 `final_test_proposal` 사이트에만 속함.
- Source와 개발 사이트가 최종 시험 사이트와 겹치지 않음.
- 건물별 적응 정답과 시험 정답 timestamp 교집합이 0.
- 모든 모델·예산·시드의 시험 정답 timestamp가 일치함.
- forecast origin 이후의 실제 전력이나 관측값이 입력·정규화·모델 선택에 포함되지 않음.
- Source 정규화·모델 선택에 최종 시험 건물 자료가 포함되지 않음.
- 각 평가창의 X=24, y=24이고 X 마지막 시각과 y 첫 시각이 1시간 차이.
- 하루 1회 28개 창이고 y 창 사이에 중첩이 없음.

구조 검증에 실패하면 성능표를 만들지 않고 오류 manifest를 저장한다. 시간 구간이나 건물을 바꿔 같은 결과 파일을 덮어쓰지 않는다.

### Gate 2 — 단일 고정 실행

- 고정 artifact로 Source-only, 다섯 적응 예산, 두 기준선의 예측을 한 번 생성한다.
- 예측값·정답·timestamp·건물·사이트·시드·예산을 원자료 수준으로 보존한다.
- 결측을 보간하지 않고, 정상적으로 기록된 0을 삭제·결측 변환하지 않는다. 음수나 장기 0은 승인된 제외 규칙이 없는 한 사후 성능을 근거로 제거하지 않는다.
- metric 계산은 저장 예측에서 독립적으로 한 번 재계산한다.
- 자동 재계산과 실행 metric 차이가 `1e-10`을 넘으면 분석을 중단하고 원인을 기록한다.
- 성공·실패·`NA`를 모두 보존하고 실패한 건물을 조용히 제거하지 않는다.

### Gate 3 — 분석 잠금과 편차 기록

- 고정 수식으로 H1, H2, H3, F1~F4, 전체 예산 곡선과 특성 탐색을 산출한다.
- 최종 결과를 본 뒤 시험 기간, 건물 구성, 학습률, epoch, 입력 특성, 임계값, 대표 사례 규칙을 바꾸지 않는다.
- 소프트웨어 결함 수정이 불가피하면 기존 실행을 보존하고 새 버전·원인·영향 범위·새 해시를 addendum으로 남긴다.
- 수정이 핵심 endpoint에 영향을 주면 최초 실행의 확정 분석 상태를 `invalidated_by_software_error`로 표시한다. 조용히 교체하지 않는다.

## 12. 선행연구와의 관계

제공 PDF *Transfer Learning on Transformers for Building Energy Consumption Forecasting - A Comparative Study*는 BDG2에서 multi-source zero-shot, target fine-tuning, 데이터 특성과 악화 사례를 이미 다루었다. 문서는 동료심사를 거치지 않은 preprint로 표시되어 있다. 따라서 현재 연구의 주장은 전이학습이나 미세조정의 최초 적용이 아니라 다음의 더 세분화된 검증으로 제한한다.

선행 PDF와 현재 C0는 입력, 전처리, 모델, 분할, 정규화, 평가창이 다르므로 절대 MAE·RMSE로 모델 우열을 직접 비교하지 않는다.

## 14. 현재 미확인 사항과 한계

- 최종 시험에서 사용할 정확한 건물 수와 건물별 시간 경계는 아직 승인·동결되지 않았다.
- 최종 시험 건물이 고정 28개 창과 모든 적응 예산을 실제로 충족하는지는 전력 열을 읽지 않았으므로 이번 문서에서 확인하지 않았다.
- 최종 시험 사이트 수는 기존 배정상 9개이지만, 실제 채택 건물이 있는 사이트 수는 최종 manifest가 정해져야 확정된다.
- 계량값의 개별 건물 측정 경계가 완전히 같다는 공식 근거가 없어 규모 특성은 물리적 총소비량 차이로 단정할 수 없다.
- 개발 특성 상관은 12개 건물·6개 사이트에서 여러 후보를 탐색한 결과라 선택 편향 가능성이 있다.
- 이 프로토콜은 C0 전이학습·적응 분석만 다루며 기상·실내·재실 센서 효과와 Transformer 비교를 검증하지 않는다.
- 최종 시험을 실행하지 않았으므로 어느 가설도 독립 검증되었다고 말할 수 없다.

## 15. 승인 후 예상 산출물

- 최종 코호트·시간·분석 protocol manifest와 해시.
- 구조 검증 로그와 중단/통과 상태.
- 원시 예측·정답·timestamp 표.
- 건물×시드×예산 metric과 데이터 효율성 표.
- F1~F4 사건표, 반복 실패표, 대표 사례 그래프.
- 사전 가용 특성표와 탐색 연관성 표.
- 개발 탐색과 최종 시험을 분리한 최종 보고서.

연구자의 승인 없이는 위 최종 시험 산출물을 생성하지 않는다.
